# 06 · 画布重设计（HTV v2 → v3 修正版：创作台画布）

> 状态：规划中（v3 修正）· 修正原因：v2「纵向 4 泳道长页」偏文档流，RHTV 味不足。
> v3 目标：**一张铺满视觉对象的创作画布**——时间轴 + 资产条 + 视频卡 + Agent 规划流常驻，
> 文本块收进侧板，检查器随选中联动。这才是"对标 RHTV"的可见形态。

## 0. 差距诊断（2026-08 用户质疑后的诚实复盘）

| 质疑 | 事实 | 结论 |
|---|---|---|
| 我们是 ComfyUI 的壳吗 | 不是。后端提交工作流 JSON 给本地 ComfyUI API（render.py），自身不做节点图 UI。与 RHTV 的「Agent→建工作流→ComfyUI 执行」在后端衔接方式上同构——这是**共用引擎的正确同构** | 衔接没问题 |
| 主流程照搬 HTV？ | 剧本→分镜→参考图→抽卡→成片 是行业标准短剧流程，本项目**立项时就如此**，与 HTV 同源而非照搬 | 流程不变是对的 |
| 对齐 HTV 改变了什么？ | **阶段 A 可见变化≈0**（只是旧界面重构+参考图面板）；R1 也只是旧面板套壳。真正的观感变化被我排在 R3/R4 | **交付节奏错了：该先把"观感质变"做出来** |
| HTV 界面不是这样 | 对。RHTV 观感=视频片段卡/参考图/节拍时间轴/Agent 规划栏同屏铺开；v2 泳道长页≈Notion 文档 | **v2 形态定错了，v3 修正** |

**与 RHTV 观感对齐的关键（v3 相比 v2 的本质变化）**：

1. **时间轴升为画布主体**（不是长页里的一节）：全宽、带刻度尺、卡宽=时长，
   卡内直接显示**视频缩略卡/参考图卡**——视觉对象铺开，而不是文本列表；
2. **资产条常驻顶部**：角色/场景卡可被分镜引用（对齐"资产设定表先行、一致性锚点前置"）；
3. **Agent 规划流常驻右栏顶部**：步骤清单+状态+汇报，每步=人审点（对齐 RHTV「每步亮方案让人拍板」）；
4. **剧本收进侧板抽屉**（文本是原料不是主角）；
5. **成片轨紧贴时间轴**（选中片按镜号排成一条轨，拼接即预览）。

## 2. 因对齐 HTV 带来的改变清单（旧 UI → v3，可验收的差异）

| # | 旧 UI（4 步向导） | v3 创作台 | 对齐的 RHTV 点 |
|---|---|---|---|
| 1 | 4 个 tab 页面切换 | 单板面同屏：资产条+时间轴+成片轨+剧本侧板 | 同屏铺开、所见即所得 |
| 2 | 分镜=表格/网格管理列表 | 节拍时间轴：卡宽=时长、缩略图、刻度尺、播放头 | 节拍表↔时间轴对照 |
| 3 | 无指令入口 | AgentBar 常驻 + dry-run 动作清单 → 执行 | 指令框即核心 |
| 4 | 任务队列=独立页 | 右侧抽屉 + Agent 规划流步骤状态 | 过程全透明 |
| 5 | 资产登记页 | 顶部资产条 + 卡可引用进分镜/抽卡 | 资产设定表先行 |
| 6 | 视频在右栏缩略墙 | 每镜卡内直接是视频卡（缩略/播放/状态） | 片段卡=可二次操作对象 |
| 7 | 成片=单独页 | 成片轨贴时间轴，选中即上轨 | 剪辑编辑器内嵌 |
| 8 | 无单镜重抽按钮 | 卡角 ⟳ 重抽本镜（hover 显现） | 局部重跑不推翻整体 |

## 3. 实施顺序（重排：观感质变优先）

| 片 | 内容 | 可见变化 |
|---|---|---|
| R1 骨架（进行中） | store 扩展 + 检查器壳 + 无 tab App | 低（基础设施） |
| **R2 画布主视觉** | 资产条 + 分镜时间轴（BeatCard 含视频/参考图缩略 + BeatRuler）+ 成片轨 | **高：一眼不再是旧界面** |
| R3 检查器保真 | ShotFields 共用 + 参考图/候选墙/A-B/选中原因迁移 + 卡级重抽 | 高 |
| R4 Agent 规划流 + 侧板 | 剧本侧板抽屉 + AgentBar 联调 + 规划流人审点 | 高 |
| R5 视觉打磨 | 卡质感/播放头/动效/空态 | 中 |

> R1 完成后**废弃「4 泳道长页」呈现**，只保留其基础设施（store/检查器壳/无 tab 壳）。
