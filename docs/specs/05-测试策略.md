# 05 · 测试策略（TDD 约定与 seams 清单）

> 状态：规划中 · 本文件是全部测试的"接缝登记册"，新增 seam 必须先在此登记并确认

## 原则（对齐 .agents/skills/tdd）

1. **只测公共 seam**：测试描述行为，不描述实现；重构不得破坏测试。
2. **垂直切片**：一次一条 spec 切片——先写一个失败测试（red）→ 最小实现（green）→ 下一片；禁止先写全部测试再写全部实现。
3. **期望值独立来源**：断言用已知字面量/工作实例，不用与实现同构的复算（防 tautological）。
4. **领域词汇**：测试类/方法命名用 `CONTEXT.md` 规范词（Shot/Draw/Candidate/Selected/Provider/…）。
5. 运行基线：`python -m unittest scripts.test_core -v`；新模块测试并入 `test_core.py` 或独立 `test_<module>.py`（均 stdlib unittest）。

## Mock 约定

- 网络一律 mock：`unittest.mock.patch('urllib.request.urlopen')` 返回假响应对象（`read()` 给 JSON 字节）；
- 不 mock `common.load_config` 的解析逻辑；配置测试用临时目录写 `config.yaml`（`tempfile`）；
- 测试不得联网、不得触 ComfyUI/ffmpeg。

## 反模式清单（评审必查）

- 断言内部字段（如 urllib Request 的 header 顺序）——耦合实现；
- 期望值由被测函数同构计算——tautological；
- 一次提交铺一大片测试不跑实现——横向切片；
- 测试名用"test1/test2"或实现词汇而非领域行为。
