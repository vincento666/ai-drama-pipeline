## 核心理念（来自业界方法论，直接映射到本骨架）

1. **资产先行（Asset-First）**：开工前先建角色定妆照/场景/道具资产库，人物一致性靠资产约束而非提示词祈祷 → `assets/` + 角色圣经。
2. **关键帧驱动（Keyframe-Driven）**：先出首尾帧图，再让模型插值 → H3 的 `image_start`/`image_end` 工作流（`06`）。
3. **批量抽卡-人工挑选**：脚本只负责编排与校验，**每次生成都留人工确认点**，人只做判断 → `pipeline.py` 的交互式确认 + `08`。
4. **单素材一职责**：一个参考图只锁定一个角色/场景（H3 参考配额 9图+3视频+3音频）→ `04-资产库管理.md` 命名规范。
5. **提示词模板化**：结构化三段式 / 时间轴格式写死为模板 → `prompts/`。

## 硬件决策速查（详见 01）

- 生成引擎（跑 H3）**不必是本机**：ComfyUI 支持远程访问，本机只跑编排脚本。
- 显存参考：16GB（RTX 4080/5080 级）跑 NVFP4 量化约 15.5GB，够用；8GB 需 GGUF 更深度量化（速度慢）；24GB 舒适；Mac Apple Silicon 可用 MPS 但 33B 模型极慢，不建议作为主力。
- 云端兜底：AutoDL / 火山引擎 / RunPod 等按小时租 24GB 卡，跑完即退，成本可控。

## 每条流水线的完整链路（一集）

```
[人] 定选题 → [AI] 剧本(四幕) → [人] 审剧本
→ [AI] 素材清单(C/S/P) → [人] 选生图模型并生成定妆照/场景图
→ [AI] 分镜(8-12格) → [人] 改分镜
→ [AI] 逐镜生成(首尾帧/引用图) → [人] 抽卡挑选
→ [脚本] 校验完整性 → [人] 粗剪/配音/调色(剪映)
→ [脚本] 拼接 → 发布
```

人出现在 6 个决策点，其余全部自动化。
