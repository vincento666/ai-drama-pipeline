# 前端重构设计方案 v1（任务优先信息架构）

> 目标：对齐 LHH 的 agent harness 概念与主流"所见即所得"产品（AI PPT / AI 文档）布局——**左侧对话驱动，中间内容即所得，右侧状态可折叠**。保留传统人机交互界面，AI 生成内容人类随时可改、可回滚，执行结果实时反馈。
>
> 现状事实依据：docs/PROGRESS.md、docs/specs/10-agent编排架构.md、docs/09-前端工作流设计.md，探查报告（web/vue 组件清单、server.py 端点清单、LHH vendor 结构、设置页 bug 根因）。

---

## 0. 设计原则

1. **任务优先信息架构（Task-first IA）**：每个界面 = 一个明确任务。用户在任何时刻只面对一个主任务 + 有限辅助任务，不堆砌。
2. **渐进式披露（Progressive Disclosure）**：默认只展示当前任务所需；细节（工具调用日志、候选详情、历史版本、高级设置）点击展开。
3. **对象-动作-反馈（Object-Action-Feedback）**：界面元素都是"对象"（会话/文档/镜卡/任务），动作明确（点击导航/拖拽/编辑/重抽），每个动作有即时反馈（状态点、diff 高亮、进度条、toast）。
4. **单一入口，零重复**：同一功能只有一个入口、一个按钮；同一信息只在一个位置显示。
5. **AI 与人工并存**：AI 可写一切，人类可改一切，可回滚。

## 3. 左栏 AI（唯一 AI 入口）

### 3.1 会话模型（对齐 LHH + 统一调度）

- **一个对话窗**：不再区分"内置对话 / 外部委派"两个入口。LHH 无 session 概念（一次任务一个 run），本项目在 LHH 之上加**会话层**：`会话 = 绑定项目的独立对话线程 + 上下文 + 任务队列`。
- **manager 统一规划分派**：会话里的每句自然语言 → 后端 manager 解析意图 → 规划任务 → 派发 executor（kimi/codex/claude/dsh 适配器）→ auditor 校验（v1 可空跑）→ 结果写盘 → SSE 推送前端。
- **会话隔离**：同一项目多个会话，上下文/任务互不干扰；切换项目 → 会话列表跟随过滤。

### 3.2 结构（自上而下）

1. **会话条**：当前项目会话列表（标题 + 状态点：空闲/运行中）+ 新建会话按钮。右键/悬停：重命名、删除、归档。
2. **对话窗**（消息流）：用户消息 / AI 回复 / 工具事件卡片（渐进式披露：默认折叠，展开看细节）/ 产物卡片（剧本段落、镜卡、候选图，点击定位到中栏对应对象）。
3. **输入框**：唯一自然语言入口（替代 AgentBar + AgentDock 输入 + OnboardPanel 访谈输入）。Ctrl+Enter 发送。
4. **会话头部**：当前会话名 + 当前模型/适配器（点击 → 快速切换模型，跳设置页①）。

### 3.3 访谈概念已删除（对话即访谈）

不设"访谈"概念、不设计访谈流程、不纠结何时何地访谈。**左栏对话本身即访谈**：任何一句话切入视频制作工作流（或触发某个 skill）即视为访谈自然发生。OnboardPanel 废弃（含 localStorage 简报标记），创作简报由对话自然产出，落在中栏剧本文档"创作简报"卡片（可编辑、可折叠）。

### 3.4 宽度

左栏默认 360px，拖拽手柄 280–640px 可调；可折叠为 48px 图标条（会话计数角标）。

## 4. 中栏 主工作区（所见即所得）

一次显示一个视图，由右栏锚点切换（锚点点击即导航）。视图与现有实现映射：

| 视图 | 内容（渐进式披露分区） | 现状来源 |
|---|---|---|
| **剧本** | 创作简报卡片（可折叠）+ 剧本正文编辑器（小说 + 分节 AI 编剧 + 预览） | ScriptPanel + OnboardPanel 产物 |
| **美术·资产** | 资产登记/上传/删除/分组 + 风格条（C/S/P/R）+ 资产预览条 | ArtPanel + AssetStrip |
| **分镜**（含运镜·抽卡） | 时间轴/网格画布 + 镜卡字段编辑（含**运镜**=camera 字段，就地编辑）+ 抽卡候选墙/质检/选片/A-B | BoardCanvas + Inspector + CandidateWall + ShotFields |
| **成片** | 片段轨 + 拼接 + 成片预览 | ComposeTrack |

- 每个视图顶部：**视图标题 + 上下文动作**（仅当前视图相关，如分镜=「保存」「从剧本生成」，成片=「拼接成片」）。其他动作一律在左栏对话里用自然语言触发——**AI 能做的，按钮不再重复**。
- 传统表单控件保留（镜卡 9 字段、资产表单等），与 AI 写入内容同屏——"既保留传统人机交互，又新增对话入口"。

## 5. 右栏 状态/导航栏（可折叠）

自上而下：

1. **阶段导航锚点**（对象-动作-反馈的合并控件）：
   - 4 项：剧本 / 美术·资产 / 分镜 / 成片（标题点击 → 切换中栏视图）
   - 每项带**状态点**：未开始(灰) / 进行中(蓝) / 完成(绿) / 有 AI 活动(脉冲)
   - 吸收原 PlanFlow（剧本/美术/分镜/抽卡/成片 5 步状态条）与顶栏锚点的职责，删除原组件。
2. **执行状态**：当前任务队列（吸收 JobDrawer：运行中任务、进度条、取消按钮）、Agent 活动摘要（manager 正在执行哪一步）、上下文消耗（会话 token/压缩状态）。

折叠：边缘手柄可折叠为 0（完全隐藏）或 24px 窄条（显示总状态点）。默认展开 300px。

## 6. 设置页（⚙ 全局唯一入口）

打开方式：顶栏齿轮 → 全屏遮罩居中对话框（720px），内部左侧 3 个子菜单导航。

### 6.1 子菜单① 本地 Model Provider

- 适配器列表（kimi / codex / claude / dsh）：cmd、args、timeout、skills_dir 增删改（现状字段保留）
- 默认适配器、最大委派轮数、Auditor 开关
- 每项 **「测试连通」** 按钮 → 后端试运行（`--version` 或空跑），结果显示在行内

### 6.2 子菜单② 外部 Harness Agent 配置

- **自动检测**（复用 `lhh_status()`：available / source / version / dsh_cli / win_loop / sync / reused）
- 「重新检测」按钮；「可调用性测试」按钮（最小 run 或 `--help` 试跑）
- 未安装时显示安装/同步指引（vendor submodule 状态 + `git submodule update --remote`）

### 6.3 子菜单③ Harness 运行设置

- **上下文压缩阈值**：数值输入（会话上下文超阈值 → 摘要压缩，见 §9）
- **Skill 管理**：新增后端 `/api/eco` 端点（复用 scripts/eco.py：list / check / install / refresh），列出可用 skill + 安装状态 + 安装按钮

### 6.4 设置页 Bug 修复（P0，先修后建）

根因：`config.yaml:94` `claude: args: []` → `common.py:86` 把标量存为字符串 `"[]"` → 前端 `AgentDock.vue:379` `.join` TypeError → 表单不渲染。

修复三处：
1. `common.py` parse_yaml_subset：`value == '[]'` 解析为空列表（对 `- ` 列表语法同样兼容）
2. `server.py` `/api/config-agent`：返回**归一化类型**（args→list、timeout→int、audit.enabled→bool）
3. 前端 `Array.isArray` 防御 + 友好错误提示

## 7. 会话模型后端 API（新增）

数据落盘：`profile/sessions/<project>/<session-id>.json`（meta + messages + tasks，滚动保留，超上限归档）。

| 端点 | 说明 |
|---|---|
| `GET /api/sessions?project=` | 会话列表 |
| `POST /api/sessions` | 新建（绑定项目） |
| `DELETE /api/sessions/<id>` | 删除 |
| `GET /api/sessions/<id>/messages` | 历史消息 |
| `POST /api/sessions/<id>/chat` | 发消息 → manager 编排 → 异步执行 |
| `GET /api/sessions/<id>/tasks` | 会话任务队列 |

现有 `/api/agent-chat`、`/api/agent-command`、`/api/agent-edit`、`/api/patch` 收敛为会话 chat 后端的内部步骤（前端不再直调）。

## 8. Agent 调度骨架（manager → executor → auditor）

- **manager**：解析意图 → 规划步骤（复用 `/api/flow-templates` 7 卡做建议，渐进式披露在会话里展示）→ 按步骤派发 executor → 汇总
- **executor**：现有适配器（kimi/codex/claude/dsh）经 agentbridge.run_loop（Windows 循环，LHH manager.run 因 POSIX 原语不可用）
- **auditor**：v1 空跑占位（配置开关已存在），后续接 LHH `parse_audit_report`
- 任务状态实时进右栏执行状态区（SSE 推送）

## 9. SSE 实时通道 + 事件回显（重点做实，核心关键功能）

### 9.1 通道

`GET /api/events?project=&episode=`：text/event-stream（标准库实现，事件总线 + 15s 心跳）。

| 事件 | 载荷 | 前端动作 |
|---|---|---|
| `rev` | `{rev}` | 替代 5s 轮询主通道（轮询保留为兜底） |
| `job` | `{id,state,progress,msg}` | 右栏任务进度实时更新 |
| `session.msg` | `{sessionId,chunk}` | 左栏对话流式渲染（打字机效果） |
| `trace` | `{sessionId,event}` | 事件进度条追加（见 9.2） |
| `doc.diff` | `{doc,range,inserted}` | 中栏文档 diff 高亮 + 撤销按钮 |
| `settings` | `{}` | 设置页刷新 |

### 9.2 事件进度条（EventTrace.vue，垂直样式）

- 位置：左栏会话消息内（agent 回合内嵌），**默认折叠为单行标题**
- 标题：**暗夜绿 + 流光动画**（CSS 渐变扫光 background-clip: text）
- 展开后为**垂直时间线**：每个事件一行 = [状态图标] 事件标题（子任务名/命令/搜索内容）+ 回执摘要
- 状态图标：执行中=**转圈动画**；成功=**✓ 打勾**；失败=✕；跳过=–
- 事件类型：`subtask`（子任务）/ `command`（命令）/ `search`（搜索/检索）/ `tool`（skill/工具）/ `patch`（写盘）

### 9.3 流式输出

`session.msg` chunk → 消息流打字机渲染；长回复默认折叠为摘要，点击展开全文（渐进式披露）。

### 9.4 可观测可审计（回执记录）

- 每个事件带回执：`ts / kind / detail / ok / result 摘要 / exit_code`
- 持久化：`profile/sessions/<project>/<id>/events.jsonl`
- API：`GET /api/sessions/<id>/events`
- 前端：会话内「执行记录」入口 → 只读审计时间线（同 9.2 样式，可筛选类型/状态）

## 10. 文档版本 / diff / 回滚

- 复用现有快照基础（profile/snapshots、diffs，taste.py 已实现同类机制）
- AI 每次写盘前自动快照；手动保存也快照（每文档上限 20 份）
- `doc.diff` 事件 → 中栏高亮新增行（绿色 3s）+「撤销」按钮（回滚上一快照）
- 新增端点：`POST /api/docs/<doc>/snapshot`、`GET /api/docs/<doc>/revs`、`POST /api/docs/revs/<id>/restore`
