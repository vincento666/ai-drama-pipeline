# 13 · 竞品调研与复盘（Toonflow / RunningHub RHSTORY）→ 流程重构

> 2026-08-13 · 调研对象：HBAI-Ltd/Toonflow-app（开源短剧工厂）+ RunningHub（含 RHSTORY 短剧专家）
> 调研方式：GitHub README/仓库结构 + RunningHub 官网/官方博客教程 + 公开视频/社区评测
> 结论先行：**Toonflow 与 RHSTORY 都是与本项目同类的「想法→剧本→分镜→成片」业务流程**，
> 但两者都是**项目化 + 资产先行 + 画布/卡片式分镜 + 单镜可调**，而本项目是**线性向导 + 表格分镜**，
> 这正是「难用、不合理」的根因。

---

## 1. 三个产品的业务流程确认（是否同类？）

| 阶段 | 本项目 | Toonflow | RunningHub RHSTORY |
|---|---|---|---|
| 入口 | 小说/素材 | 原著/剧本 | **有想法 / 有剧本** 双入口 |
| ① 剧本 | 小说→事件→骨架→剧本（4 步手动） | 章节事件提取→ScriptAgent 自动骨架/改编策略/结构化剧本 | Step1 剧本创作（一个 Prompt 直接出剧本） |
| ② 美术/资产 | 资产登记 C/S/P + 角色圣经 | 角色/场景/素材（画布节点） | Step2 美术设定（角色/场景/道具/整体风格） |
| ③ 分镜 | **markdown 9 列表格** | **cornerScape 分镜图 + 无限画布节点** | Step3 分镜设计（景别/动作/运动/情绪/时长） |
| ④ 出片 | 逐镜抽卡→选片→ffmpeg 拼接 | 分镜图节点化精调→拼接导出 | Step4 短片生成（左描述右预览，单镜可调） |
| 组织形态 | **线性 9 步向导 + 三栏** | **无限画布（自由编排/回溯/并行）** | **项目化分阶段 + 节点/Agent 对话框融合** |

**结论：三者业务本质相同**（都是「故事 → 资产 → 分镜 → 视频 → 成片」），
Toonflow/RHSTORY 已把这条链做成「项目化、资产先行、可视化分镜、单镜可调」，
本项目停留在「线性 CLI + 表格」。

## 2. Toonflow 完整画像（HBAI-Ltd/Toonflow-app）

- **数据**：GitHub **13.8k★** / 2.5k fork，Apache-2.0 + 补充商业协议（对外分发 2+ 第三方需授权；
  ≤5 法人内部使用/平台分账/个人学习永久免费），Electron 桌面端 + Web（Docker）。
- **技术栈**：Node.js + Express 5 + SQLite + Socket.IO；Vercel AI SDK（OpenAI/Anthropic/Google/DeepSeek/
  智谱/MiniMax/通义/xAI）；本地 ONNX 向量检索；Sharp 图像处理。
- **官方 Demo 成本**：约 **¥130/2分钟成片**（LLM ¥10 + 视频 ¥120 + 图 ¥1）；视频 Seedance 2.0、
  图片 GPT Image 2 / Nano Banana Pro、LLM Claude Opus 4.6。默认账号 `admin/admin123`。
- **核心功能（README 原文）**：
  1. **无限画布生产工作台**：剧本/角色/分镜/素材/视频皆节点，自由编排、回溯、并行。
  2. **三层 Agent 协作**：决策层 / 执行层 / 监督层，覆盖任务拆解、生成、审阅、修订反馈。
  3. **持久化 Agent 记忆**：本地 ONNX 向量，短期消息 + 长期摘要 + 语义召回，跨会话连续。
  4. **可编程供应商**：设置中心直接写 TS 逻辑即时生效（多模型/私有化）。
  5. **章节事件图谱**：自动提取原著章节事件结构化存储，改编按图谱调上下文。
  6. **Skill 文件化**：ScriptAgent/ProductionAgent 核心提示词外化为 Markdown，在线编辑调优。
- **关键动作**：`src/agents/` 只有 **scriptAgent + productionAgent 两个 Agent**，把「编剧」和「生产」
  收拢成两大块；`routes/` 里 `cornerScape`（分镜）、`assetsGenerate`（素材批量生成）、
  `artStyle`（画风管理）是独立模块——**分镜是独立的一等公民，不是表格**。

## 3. RunningHub 完整画像

- **定位**：原生 AI 智能体驱动的一站式内容创作平台（ComfyUI 工作流 + 无限画布 + AI 应用 +
  模型 API），本质是「云端 ComfyUI + 工作流市场 + 创作产品矩阵」。
- **产品矩阵（顶栏）**：模型API / AI应用API / 工作流API / **RHTV** / **无限画布** / **RHSTORY** /
  快捷创作 / VibeX / AI 应用 / ComfyUI 工作流 / Labs。
- **模型**：Seedance 2.5（0.21元/秒）、MiniMax H3（768P，年卡低至 0.12元/秒）、Seedream 5.0 Pro、
  VibeX（每日 100 亿 Token）、Wan 2.2 / Qwen-image / Kontext 节点。

### 3.1 RHSTORY（短剧专家）—— 与本项目最直接对标
官网 slogan：**「自动拆解剧本、生成分镜，一键输出影视级大片」**。
官方教程明确其 4 阶段：

1. **剧本创作**：首页「**有想法**」/「**有剧本**」两个入口。有想法时只需一段故事描述
   （类型+人物+冲突+走向），系统产出剧本。
2. **美术设定**：确认**角色设定 / 场景设定 / 道具设定 / 整体风格**（比例、色调、质感）——
   **资产先行，先锁定再分镜**。
3. **分镜设计**：把剧情拆成具体镜头，确定**景别、人物动作、镜头运动、情绪、时长**；
   强调「每个镜头承担清晰功能（交代环境/引入角色/制造异常/传递线索/人物反应）」。
4. **短片生成**：镜头列表；**左侧画面描述（时间范围/景别/动作/运动/环境声/对白），
   右侧预览已生成视频**；为每镜关联角色/场景/道具/图/视频/音频素材；**单镜可调，无需整项目重生成**。

社区反馈关键句：
- 「说出一个想法，它就能把剧本/小说/IP 故事**自动拆解成项目、剧集、场次、镜头**，一键生成」
- 「全流程可控，**可批量生成，预设提示词，抽卡少**」
- 「**一键 25 分镜 + 15 秒视频**」全自动化
- 「RHTV 终于把**节点式操作和 Agent 对话框**整合到一起」

### 3.2 RHTV / 无限画布 / 快捷创作（对流程的启示）
- **RHTV**：AI 视频/图像生成画布，多步骤工作流 + 分镜设计 + 视频逐帧修改；节点 + Agent 对话框融合。
- **无限画布**：与 Toonflow 同源思路，创作不绑定线性步骤。
- **快捷创作**：Seedance 2.0 4K 商品图/人物照/品牌素材 → 广告视频（单图/单段快速出片入口）。

## 5. 复盘：本项目流程「难用、不合理」的具体原因

1. **线性向导违背创作直觉**：9 步（小说→事件→骨架→剧本→资产→分镜→抽卡→选片→拼接）强制串行，
   用户想改一个镜头要「回到分镜表→改→重新抽卡」；Toonflow/RHSTORY 都是画布/项目化，可跳回、可并行。

2. **分镜是「表格」而不是「可视化分镜」**：9 列英文字段（wide/medium/push in…）对非专业用户极不友好；
   RHSTORY 是「镜头卡片 + 左描述右预览」，Toonflow 是「分镜图节点」。**这是难用的最大来源。**

3. **美术设定（资产）没前移、没闭环**：资产只是「登记 + 图片 + 圣经」，与分镜、生成是松耦合；
   RHSTORY 明确「**先美术设定（定妆照/场景图/风格）→ 再分镜 → 生成时强关联**」。

4. **抽卡/选片逐镜手动、无批量编排**：每镜要点「抽卡」→等待→选片；RHSTORY「一键 25 分镜 + 批量生成，
   抽卡少」；本项目缺「为全部镜批量抽 N 候选 + 统一缩略图墙」。

5. **中间概念过载**：把「事件图谱 / 故事骨架 / 分集决策 / 资产登记」全部暴露成手动步骤；
   用户要的是「想法→成片」，Toonflow 把这些收拢进 **ScriptAgent 一键完成**，中间产物只是可展开的副产物。

6. **成片无预览/时间线**：ffmpeg 硬拼，缺时间线排序、转场、逐段定位（v3 路线图仍未做）。

7. **「向导+三栏」交互与「抽卡候选墙」割裂**：抽卡在右栏小格子里，候选多了体验差；
   缺 RHTV 式的「节点 + Agent 对话」融合。

## 6. 流程重构建议（对标后）

> 目标：**把主干收敛成 RHSTORY 的 4 阶段「剧本 → 美术设定 → 分镜 → 成片」，
> 其余降级为自动副产物；保留本项目差异化（本地免费出片 + 品味学习 + 生态加载 + Ref2VA）。**

### P0（立即可做，直击难用）
1. **重排主干为 4 步**：剧本 → 美术 → 分镜 → 成片；事件/骨架/资产清单改为「一键 AI 编剧」内部自动产出，
   前端只显示可展开的结果卡片，不强制 4 个手动子步骤。
2. **分镜表 → 分镜卡片**：每镜一张卡片（缩略图 + 景别/运镜/时长下拉 + 对白 + 角色/场景/参考图槽位），
   替换 9 列表格；保留 分镜.md 作为底层数据（CLI 兼容）。
3. **美术设定前移并强关联**：新增「美术设定」视图（角色定妆照 + 场景图 + 整体风格 + 色调），
   分镜引用资产 = 生成时 Ref2VA 参考图的来源；`/api/render` 已支持 ref，补齐 UI 关联即可。

### P1（对齐核心体验）
4. **批量抽卡**：一键「为全部镜抽 N 候选」→ 统一缩略图墙（已有候选墙，扩到全局）+ A/B 对比（已做）。
5. **单镜重抽**：某镜不合格，只重抽该镜，不动其他（`render --only` 已支持，补齐 UI 入口）。
6. **成片时间线预览**：compose 前的时间线排序 + 分段起止时间（FR6）。

### P2（生态借力，非必做）
7. **节点/画布式组织**：对标无限画布（可选，重活）；或先做「项目化标签页 + 任意跳转」。
8. **可编程供应商 / 画风管理**：config 已有雏形，画风管理并入 taste.md 扩展。

### 差异化（继续守住，别被带偏）
- 本地 ComfyUI **免费出片**（Toonflow/RHSTORY 都是云计费，这是本项目最大卖点）；
- **品味学习**（selection_log + diffs + taste.md）——竞品是「创作连续性」，我们做「审美自动化率」；
- **生态加载器 eco.py**（motion-context/blockcache/prompt-skill）；
- **Ref2VA 人物一致性**（资产先行 + 参考图强约束）。

---

## 7. 一句话总结

**我们的业务方向没错，错在「把引擎实现了、把体验做成了表格和向导」。**
对标 Toonflow 的「无限画布 + 双 Agent + 资产先行」和 RHSTORY 的「4 阶段 + 卡片分镜 + 单镜可调」，
下一步应**重排为 4 阶段主干、分镜卡片化、美术设定前移、批量抽卡**，同时守住「本地免费出片 + 品味学习」的差异化。

## 8. 实施进展（2026-08-13 P0 已落地）

- ✅ **4 阶段主干**：前端向导收敛为「①剧本 → ②美术 → ③分镜 → ④成片」（App.vue），
  事件/骨架/资产降级为「一键 AI 编剧」内部副产物（`POST /api/ai-write-all` + `ai_writer.chain`）；
- ✅ **分镜卡片化**：BoardView 由 9 列表格改为**卡片式**（每镜一卡：景别/运镜/时长下拉 + 角色/场景/灯光 + 对白），
  底层仍读写 分镜.md（CLI 零改动兼容）；
- ✅ **美术设定前移**：新增 ArtPanel（角色定妆照/场景图/道具/整体风格，`/asset-img/<code>` 服务资产图），
  作为独立第 2 步，先锁定资产再分镜；
- ✅ **成片视图**：新增 ComposePanel（选中清单 + 成片预览 + 拼接），闭环第 4 步。

保留未动：本地 ComfyUI 免费出片、品味学习、eco.py、Ref2VA、质检徽标（FR3）、A/B 对比（FR4）。

下一步（P1）：批量抽卡（一键为全部镜抽 N 候选）、单镜重抽入口、成片时间线预览。
