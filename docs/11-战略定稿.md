# 11 · 战略定稿：借力 Agent Harness + 垂直记忆层 + 两阶段路线

> 2026-08-11 定稿 · 用户战略确认
> 一句话：**不自研 agent harness，借力主流 harness（其 agent 管理与执行、基础记忆）；
> 我们做一层"垂直 AI 视频制作"的记忆层（偏好/品味）专供 harness 使用；
> 后台 CLI 给 agent 感知/调用/控制，前台极致简约给人审核/编排/校验；
> 路线：先按本项目需要完整复刻 Toonflow 功能面（吸取最大能力范围），
> 再走自己的路——连接社区生态"借力"，以优秀创作体验快速实现用户目标。**

## 1. 架构总纲（前后台分工）

```
┌────────────────────────────────────────────────────────────┐
│  前台（人）：极致简约 · 审核 · 编排 · 校验                  │
│  7 步创作向导 + 候选画廊点选 + 成片预览（web/ 已实现）        │
└──────────────────────────┬─────────────────────────────────┘
                           │ HTTP API
┌──────────────────────────▼─────────────────────────────────┐
│  本项目（编排中枢 = 后台 CLI，供 Agent 感知/调用/控制）        │
│  pipeline / render / eco / taste / ai_writer / compose       │
│  + 垂直记忆层：品味档案（taste.md + selection_log + diffs）    │
└──────┬──────────────────────────────┬──────────────────────┘
       │ ComfyUI API                  │ 生态加载（eco.py）
┌──────▼─────────┐            ┌───────▼──────────────────────┐
│ ComfyUI 引擎    │            │ 外部 H3 skill/插件/工作流      │
│ (T2VA/I2VA/    │            │ motion-context / blockcache / │
│  Ref2VA/FL2VA) │            │ prompt-skill / auto-short-drama│
└────────────────┘            └──────────────────────────────┘
```

**Agent harness 关系**：主流 harness（Reasonix/Codex/Claude 等）是执行者——
通过本项目 CLI 感知项目状态（剧本/分镜/候选/品味）、调用能力（生成/质检/拼接/加载生态）、
读写垂直记忆（品味档案）。**本项目不实现 agent 循环/工具路由/向量记忆，这些借力 harness**。

## 2. 垂直记忆层（本项目唯一自研的记忆，专供 harness）

Toonflow 的记忆 = 创作连续性（会话摘要/向量召回），绑死在其 App 内。
**本项目做的是"为 harness 服务的垂直记忆"**：AI 视频制作领域的偏好与品味——

| 记忆载体 | 内容 | 谁读写 | 状态 |
|---|---|---|---|
| `profile/taste.md` | 风格基调/镜头偏好/对白风格/避免项/用户声明 | 人维护 + Agent 提炼（需确认） | ✅ |
| `profile/selection_log.jsonl` | 每镜选中/淘汰（A/B 信号） | 自动采集 | ✅ |
| `profile/diffs/` + `stats.json` | 草稿→定稿 diff、修改率趋势（自动化率） | 自动采集 | ✅ |
| `/api/taste` | 记忆的机器接口（前端插入行默认值/Agent 读取） | Agent + 前端 | ✅ |

原则：**人先画框（框架/脉络/节奏），Agent 在框内打稿，人再审改打磨**；
一切 Agent 产出是草稿；品味提炼需人确认（禁止无证据编造）。

## 3. Toonflow 功能面清单（源码/README 级核实）→ 复刻差距

### 3.1 Toonflow 有、我们缺（按"本项目需要"的复刻优先级）

| 功能 | Toonflow 实现 | 本项目差距 | 复刻优先级 |
|---|---|---|---|
| 章节事件图谱 | 小说→自动提取章节事件结构化存储，改编按事件图谱调用上下文 | AI 编剧只做四幕模板，无事件提取 | P0（AI 编剧升级） |
| 任务队列/实时 | Socket.IO 全局任务队列 + 前端实时进度 | render 有 job 但无全局队列面板 | P0（前端队列面板） |
| 素材批量生成 | assetsGenerate：批量生成角色/场景图 + prompt 润色 | 只有 asset_manager CLI 登记，无批量生成 | P1 |
| 监督层（质量审阅） | 三层 Agent 决策/执行/监督，生成→审阅→修订反馈 | 单 Agent 编排，无自动修订循环 | P1（配 FR3 质检） |
| 画风管理 | artStyle 增删改 + extractStylePrompt 提取 | taste.md 是偏好非画风；可扩展画风小节 | P1 |
| 可编程供应商 | 设置中心写 TS 逻辑即时生效 | config 模型名静态 | P2 |
| 多用户/登录 | admin/admin123、多项目 | 单机无登录（本地工具可接受） | 不做 |
| 无限画布 | 类无限画布组织节点 | 我们是向导+三栏（更贴合"极致简约"） | 不做（交互差异） |

### 3.2 我们有、Toonflow 没有（差异化资产，阶段二的主场）

| 能力 | 说明 |
|---|---|
| 本地 ComfyUI 免费出片 | 开源用户核心诉求（省云端按秒计费） |
| Ref2VA 人物一致性 | 资产先行 + 参考图强约束（已实现） |
| **品味学习（垂直记忆）** | 从用户选择/修改提炼偏好减少返工（Toonflow 只做创作连续性） |
| **生态加载器 eco.py** | 一键安装/加载 H3 社区插件/skill/工作流（motion-context/blockcache/prompt-skill/auto-short-drama 已装） |
| 快速/标准抽卡模式 | ~9s vs ~48s 测试/量产切换 |
| 创作向导 + AI 编剧 | 7 步引导 + 小说→剧本双模式（LLM/Agent 指令） |

## 4. 两阶段路线

### 阶段一：按需复刻 Toonflow（补齐能力面，2026-08 起）

1. P0：AI 编剧升级（章节事件图谱：小说→事件列表→四幕剧本）、前端任务队列面板（全局 render job 状态）；
2. P1：素材批量生成（角色/场景图生成 + prompt 润色，走 ComfyUI/社区工作流）、监督层（质检 FR3 → 自动修订循环）；
3. P1/P2：画风管理（taste 扩展）、可编程供应商（config 化已有，脚本化后置）。

### 阶段二：本项目自己的路（差异化 + 生态借力）

1. **垂直记忆成为 harness 插件**：taste.py + /api/taste → MCP/skill 封装，任何 harness 可读写品味；
2. **生态借力闭环**：eco.py 已装 motion-context（跨镜连续）/blockcache（加速）/prompt-skill（提示词指令）
   → 接入 render：下一镜自动带上一镜尾帧+音频（FR5）、加速模式、Agent 用 prompt-skill 生成分镜提示词；
3. **质检 + 选片闭环**：FR3 自动质检（ffprobe/抽帧/音轨）→ 候选徽标 → Agent 自动淘汰废片；
4. **剪辑层**：剪映草稿导出（FR7）+ 后续 ChatCut MCP。
