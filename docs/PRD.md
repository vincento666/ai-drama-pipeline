# PRD · 本地化 HTV（对标 RunningHub RHTV）

> 版本：v0.2（2026-08 重新规划版）· 所有者：DSH 规划 / Kimi K3-256k 前端实现 / DSH 后端实现
> 依据：docs/specs/00-规划总览.md、01-htv对标.md、02-toonflow流程.md
> 一句话：**完全复刻对标 RunningHub RHTV 的本地化 AI 短剧/漫剧生产画布**——剧本 → 分镜 → 参考图 → 抽卡 → 成片，
> 画布式、每步可编辑、过程全透明、不抽卡盲盒；人只做判断，机器做批量生成。

## 1. 产品定位与目标用户

- **定位**：本地运行（模型/数据本地可控）的 RHTV 等价物：Agent 拆任务 → 每步落盘可编辑 → 逐镜局部重跑 → 成片导出。
- **用户**：短剧/漫剧创作者（个人与小组），无云依赖、按需调用 DeepSeek/Qwen/Kimi/本地 LLM。
- **差异**（vs RHTV 云端）：生成引擎用本地 ComfyUI + H3；模型提供商可配置；数据全部本地文件。

## 3. 关键体验原则（对齐 RHTV）

0. **不重造 ComfyUI（战略边界，2026-08 澄清）**：RHTV 的生成层本质就是 ComfyUI 工作流生态
   （RunningHub 官方有 ComfyUI_RH_OpenAPI/APICall 等插件为证）。ComfyUI 是社区标准的"生成操作系统"，
   RHTV 用它、我们也用它——**共用同一个轮子不叫造轮子**。边界：
   - 通用节点画布 → 用 ComfyUI 原生 UI（我们不做，F16 已撤销）；
   - 图/视频生成 → 一律经 ComfyUI API/工作流，本层只做「领域语义 → 工作流参数」映射（render.py/eco.py 已是正确姿势）；
   - 我们要造 = RHTV 不开放给本地的部分：**领域流程层**（剧本→分镜→参考图→抽卡→质检→选片→成片、
     资产一致性、品味记忆）+ **领域画布 UI**（分镜卡/参考图墙/选片墙，短剧专用操作面，非节点编辑器）+
     **Agent/CLI/harness 接口**。
1. **过程透明**：任何一步的产物都能看、能改、能重跑；生成进度实时可见。
2. **不抽卡盲盒**：候选墙 + 质检徽标 + A/B 对比，选片有据（选中原因留痕）。
3. **人审点固定**：选风格/确认大纲/改造型/局部重跑/剪辑微调（docs/08-人机协作判断点.md）。
4. **本地优先**：无 LLM 时降级为 Agent 指令模式（现有能力）；无 ComfyUI 时提示词/参考图照常产出。

## 4. 成功指标

- P0 验收：四步画布全流程跑通（剧本→分镜→参考图提示词→抽卡→选片→成片），单镜重跑 ≤1 次操作；
- 测试：单元测试 ≥ 当前 55 例且每新 seam 必有测试；`npm run build` 零告警零失败；
- 协作：Kimi 每切片交付后 DSH 验收记录进 PROGRESS.md，未决问题 24h 内闭环。

## 5. 变更流程

需求变更 → 更新本 PRD（版本号+1）→ 同步 docs/specs/ 对应模块 spec → PROGRESS.md 记录 → 双方按新契约执行。
