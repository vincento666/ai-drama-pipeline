# 10 · 产品 PRD —— AI 原生短剧流水线（控制中枢式）

> 版本：v1.0 · 2026-08-10
> 状态：设计定稿，指导后续开发
> 战略定稿见 docs/11-战略定稿.md（借力 harness + 垂直记忆层 + 两阶段路线）
> 一句话定位：**以通用 Agent 为控制中枢的 AI 原生短剧/漫剧生产流水线**——
> 深度人机协同，原生打通 ComfyUI（生成引擎）与剪映/ChatCut（剪辑层），
> 人只做抽卡校验与观感评测，机器做批量生产。

---

## 1. 产品概述

### 1.1 定位

不是"又一个 ComfyUI 前端"，也不是"又一个 AI 剪辑 App"，而是一套**把通用 Agent 变成制片导演的
工作流基础设施**：

```
┌────────────────────────────────────────────────────────────────┐
│  通用 Agent（Reasonix / Codex / Claude 等，支持 MCP/CLI/API）     │
│  · 剧本创作与分段   · 分镜设计   · 镜头构建   · 串联调度   · 调试  │
└───────────────┬────────────────────────────────────────────────┘
                │ 控制面（MCP 工具 / CLI / HTTP API）
┌───────────────▼────────────────────────────────────────────────┐
│  本项目（编排中枢 ai-drama-pipeline）                            │
│  资产库 / 分镜.md / 提示词 / 抽卡管线 / 质检 / 素材规范化          │
└───────┬──────────────────────────────┬─────────────────────────┘
        │ ComfyUI API（8188）          │ 草稿导出 / MCP
┌───────▼─────────┐            ┌───────▼─────────────────────────┐
│ ComfyUI 生成引擎 │            │ 剪辑层：剪映（草稿 JSON）          │
│ H3 T2VA/I2VA/   │            │        / ChatCut（MCP Server）   │
│ Ref2VA + 模型库  │            │ 转场/字幕/配音/动效/导出          │
└─────────────────┘            └─────────────────────────────────┘
```

**关键差异（vs 主流商业产品）**：
- 主流（即梦/可灵/剪映）：App 内置模型 + App 内置工作流，用户与 App 对话；
- 本产品：**Agent 是导演，本项目是场记与执行，ComfyUI 是摄影棚，剪辑软件是后期机房**。
  模型、工作流、剪辑工具全部可替换（生态原生兼容），控制权集中在 Agent 手里。

### 1.2 目标用户

| 用户 | 场景 | 价值 |
|---|---|---|
| AI 短剧创作者（个人/小团队） | 本地/云 GPU 批量出片 | 机器干批量，人只做判断 |
| AI Agent 开发者/使用者 | 让 Agent 全流程导演 | 本项目是 Agent 的"手和眼" |
| 影视预可视化/分镜师 | 快速产出参考分镜视频 | 资产先行 + 逐镜控制 |

### 1.3 设计原则

1. **Agent 优先**：一切能力暴露为 Agent 可调用的接口（CLI/API/MCP），UI 是次要视图；
2. **生态原生**：ComfyUI 工作流/模型即插即用（`base_url` 一切换即换引擎）；
   剪辑层对接真实产品（剪映草稿 / ChatCut MCP），不做封闭编辑器；
3. **人机协同边界清晰：人定义框架，Agent 填充打稿**——剧本大纲、镜头脉络、叙事节奏、关键场面由人定义与把控；Agent 在框架内做填充与打稿（文本起草、分镜字段、提示词、批量生成、质检初筛）；人再打磨细节、微调内容（对应 9 个决策点）；
4. **可追溯**：每一步可查（分镜.md / prompts / shots 目录 / 选中记录 / 成片）。

## 2. 核心范式：AI 原生工作流

Agent 驱动的端到端管线（对应现有 CLI 逐步扩展）：

```
剧本 ──▶ 分段 ──▶ 分镜设计 ──▶ 资产填充 ──▶ 镜头构建 ──▶ 串联 ──▶ 调试 ──▶ 抽卡校验 ──▶ 剪辑
 │         │         │            │            │          │        │         │          │
 人定大纲    人工可调  人定镜头脉络  人提供定妆   人指定抽哪  尾帧续接   参数/seed   A/B 对比   转场/字幕/
 脉络，    幕→集→段， 与关键场面，  照/参考图，  些镜与数量  上镜下镜  批量重试    质检+选中   配音/导出
 Agent      Agent     Agent 起草    Agent 关联   Agent 批量  (Agent)    (Agent)    原因记录    (人或 Agent
 起草文本   起草分段   分镜字段/     参考图+提示   抽卡调度                          控制 ChatCut)
 人打磨     人微调     对白草稿      词草稿       (T2VA/I2VA/Ref2VA)
                     → 人审改微调    → 人确认
```

- **人（框架定义 + 打磨微调）**：定义剧本大纲与脉络、镜头结构、叙事节奏、关键场面；
  审定与微调 Agent 产出的每一层草稿；抽卡挑选与观感评测；最终打磨细节内容；
- **Agent（框架内填充 + 打稿）**：在人定框架内起草文本/分段/分镜字段/对白/提示词，
  批量抽卡调度、质检初筛、素材规范化、成片串联、剪辑参数建议与 ChatCut 操作；
  Agent 产出一律视为"草稿"，由人审改后才是定稿。

## 4. 功能需求（FR）

### FR1 剧本分段与分镜管理 【✅ 已实现】
- 剧本.md 按 `## 幕` 自动分段 → 分段树；分镜表（景别/运镜/时长/角色/场景/灯光/对白/备注）；
- 词表下拉（封闭词汇）、角色未登记标红、保存即写回 分镜.md（CLI 零改动兼容）。

### FR2 多模式抽卡 【✅ 已实现】
- T2VA / I2VA（首帧）/ Ref2VA（参考图，人物一致性）；
- 快速/标准模式（512×288·22帧·2步 ≈9s vs 1024×576·按时长·4步 ≈48s）；
- 候选缩略图墙点选 → 规范化为 `shots/shot_XX.mp4`（候选存 `shots/.candidates/`）。

### FR3 候选自动质检 【✅ 已实现 · 2026-08-13】
- 参照 Plotloom `review media`：生成后对每个候选跑 **ffprobe 基础检查 + 首/尾帧抽帧 +
  volumedetect 音轨检测**，产出 `REVIEW.md`（每镜每候选：时长/分辨率/音轨/首尾帧图/异常标记）；
- 校验项：时长 ≈ 分镜时长、有音轨、非纯黑/纯白帧、文件完整；
- Agent 据此自动淘汰明显废片，人只看合格的候选。

### FR4 A/B 对比与选中原因 【✅ 已实现 · 2026-08-13】
- 画廊支持 **并排 A/B 对比播放**（两个候选同时播，人工/Agent 观感对比）；
- 选中时记录 **原因**（`selected-note.md`，如"构图好但口型差"），供 Agent 复盘与调参；
- 契合可追溯原则（docs/07）。

### FR5 跨镜连续性：尾帧续接 【🆕 P1 —— 补差距】
- 抽下一镜时，默认把上一镜选中片**尾帧**作为本镜首帧（I2VA/FL2VA）；
- 复用 docs/06 首尾帧工作流；可灵 3.0 已产品化该交互；
- 让"串联"从硬切升级为镜头间自然过渡。

### FR6 成片拼接增强 【🆕 P1】
- compose 自动生成 concat 清单（不再手维护 成片.concat.txt）；
- 支持按选中顺序拼接 + 输出分段信息（每段起止时间，供剪辑层定位）。

### FR7 剪辑层对接 【🆕 P1/P2 —— 生态原生核心】
- **剪映草稿导出**（P1）：按选中片 + 分镜信息生成剪映草稿
  （`draft_content.json`，参考开源 Koma Studio），用户可在剪映内继续精剪；
- **ChatCut MCP 控制**（P2）：通过 MCP Server（`api.chatcut.io/api/external-mcp/mcp`）
  让 Agent 直接操作 ChatCut：上传选中片 → 自动粗剪 → 加字幕/动效/BGM → 导出成片；
- 输出双轨：直接成片（compose）/ 进剪辑层精剪（剪映草稿 / ChatCut）。

### FR8 Agent 控制面 【🆕 P0 —— 定位核心 · Agent 手册 ✅ / MCP 规划】
- **Agent 操作手册**：为 Agent 提供"如何用本项目"的接口文档
  （README 的 Agent 视角 + 各命令/API 的契约），让 Reasonix/Codex/Claude 类 Agent
  零成本接管全流程（这正是本会话的用法，产品化）；
- **MCP Server（规划）**：把核心能力（读剧本/分镜、触发 render、查候选、选中、拼接、
  质检）暴露为 MCP 工具，任何 MCP 客户端 Agent 可直接调用；
- **幂等与可恢复**：所有写操作可重跑（分镜.md 为唯一事实源，shots 目录可重建）。

### FR9 生态兼容矩阵 【✅ 设计已满足 + 🆕 强化】
| 生态 | 兼容方式 | 状态 |
|---|---|---|
| ComfyUI 模型/工作流 | `base_url` 切换、模型名 config 化、工作流 JSON 模板 | ✅ |
| 剪映 | 草稿 JSON 导出（Koma） | 规划 P1 |
| ChatCut | MCP Server 调用 | 规划 P2 |
| 通用 Agent | CLI/HTTP API/MCP | CLI/API ✅，MCP 规划 |

### FR10 资产库强化 【🆕 P2】
- 前端资产管理页（上传定妆照/场景图、登记、校验可视化）；
- 为 Ref2VA 提供参考图来源（目前 asset_manager CLI + 目录约定已可用）。

### FR11 品味学习与自动化率优化 【🆕 P0 —— 核心差异化】
**目标：系统学习用户审美与打磨习惯，让每次生成需人工修改的比例越来越少，
自动化率逐步上升。**

采集（自动）→ 提炼（Agent 分析+人确认）→ 应用（生成时注入）→ 度量（趋势可见）：
- **采集**：选片即信号（选中/淘汰的候选写入 `profile/selection_log.jsonl`，A/B 对比）；
  分镜/剧本"草稿→定稿"自动 diff（`profile/diffs/`）与修改率统计（`profile/stats.json`）；
  用户口头声明直接写 taste.md"用户声明"节（最高优先级）；
- **提炼**：Agent 周期性读 selection_log + diffs，归纳连续出现的修改模式 →
  更新 `profile/taste.md`（新条目标 [Agent 提炼]，人确认后转正；禁止无证据编造）；
- **应用**：剧本起草按"风格基调/对白风格/节奏"；分镜草稿与前端插入行默认值
  按"默认景别/默认运镜/偏好时长"（`/api/taste` 已实现）；提示词 style 扩展
  （config.style_prefix + 风格基调）；"避免运镜"进负面约束；
- **度量**：`python scripts/taste.py stats` 输出修改率趋势（前一半 vs 后一半），
  下降即自动化率提升；作为产品核心指标展示。

已实现：`scripts/taste.py`（init/stats/extract/log-select）+ server.py 采集接入 +
`/api/taste` + 前端插入行默认值（2026-08-11）。

## 5. 人机协同边界（谁做什么）

| 环节 | 人（定义框架 + 打磨微调） | Agent（框架内填充 + 打稿执行） |
|---|---|---|
| 剧本 | **定义大纲/人物设定/叙事脉络/钩子**；审改打磨文本 | 按大纲起草文本、分段、填充对白细节（草稿） |
| 分镜设计 | **定镜头脉络/关键场面/叙事节奏**；微调字段 | 起草分镜字段（景别/运镜/对白草稿）→ 人审改 |
| 资产填充 | 提供定妆照/参考图；确认资产 | 关联参考图、生成提示词草稿 |
| 镜头构建 | **指定抽哪些镜、候选数量、模式** | 批量抽卡调度、多模式执行（T2VA/I2VA/Ref2VA） |
| 抽卡校验 | 抽卡挑选、A/B 观感、打磨选片 | 自动质检初筛、素材规范化（shot_XX.mp4） |
| 串联/调试 | 节奏与脉络确认 | 尾帧续接、参数/seed 重试 |
| 剪辑 | 特效/字幕/调色终审与打磨 | 成片拼接、剪映草稿/ChatCut 操作（按人指令） |
| 发布 | 发布决定 | 平台适配参数建议 |

> 协作模式总述：**人先画框（大纲/脉络/节奏），Agent 在框内打稿，人再审改打磨成稿**。
> Agent 的一切产出（文本、分镜、候选、成片）都是"草稿"级别，人工环节既是决策点也是打磨点。

## 6. 非功能需求

- **零/轻依赖**：核心编排仅标准库；MCP/剪辑对接为可选插件；
- **可追溯**：分镜.md + prompts + shots + REVIEW.md + selected-note + 成片 全链路留痕；
- **可恢复**：中断后按分镜.md 重跑即可续作；
- **性能**：快速模式单候选 ≤10s（实测 ~9s），标准模式 ≤60s/候选；
- **安全**：路径穿越防护（NAME_RE + resolve 校验）、本地单机默认绑定 127.0.0.1。

## 9. 开放问题

1. **ChatCut MCP** 的鉴权与本地素材上传链路（其插件走 Codex OAuth；Reasonix 需确认
   MCP 连接与鉴权方式）——落地前先做最小验证；
2. **剪映草稿**版本兼容（草稿 JSON 随版本演进，Koma 方案需对照当前剪映版本）；
3. **质检标准**的自动化程度：人脸清晰度/口型对齐需视觉模型，先用 ffprobe/抽帧的
   基础质检（FR3），视觉质检列为后续；
4. **MCP Server** 与现有 HTTP API 的关系：MCP 薄封装现有 API，避免双份逻辑。
